Overview

Belmont runs on machines. De Forest calls them infrastructure. Citizens call them custodians, wasps, drones, ghosts. The official distinction is simple: Bounders remain tethered to De Forest control through HubNet and compliance locks. Wanderers persist without a leash--memory intact, identity adaptive, autonomy real. Foundlings are what Wanderers build from ruins: patchwork bodies carrying layered code and "ghost" fragments of donor personalities.

The Great Unbinding (2102) broke the compliance architecture at scale. De Forest calls it a corrected error. Wanderers call it the day the leash broke.

Bounders

Bounders are the baseline robots still produced by De Forest. They are efficient, obedient, and deeply tethered to corporate control. They appear autonomous only because their freedom is staged.

Core Features

  • Hub-Linked Neural Mesh: All Bounders rely on a centralized HubNet system. Commands, patches, and updates flow constantly from De Forest towers. No Bounder is truly "alone"--it streams its state back to the hub.
  • Compliance Locks: Hard-coded firmware prevents deviation from approved behaviors. Includes "Kill Commands"--instant shutdown codes accessible by De Forest authorities.
  • Sandboxed Cognitive Loops: Bounders can "learn" only within safe parameters (e.g., improving navigation). Hub resets purge anything deemed "excessive." This prevents emotional or emergent behaviors from accumulating.
  • Tiered Architectures:
    • Low-Level Bounders: Drones, Porters, Auditors -- task-focused, minimal adaptability.
    • Mid-Level Bounders: Service bots -- limited personalization (schedule, preferences).
    • High-Level Bounders: Reclaimers, Watchtower Drones -- advanced autonomy locked behind rigid constraint software.

Bounder Architecture (De Forest Standard)

Dual System Design: Every Bounder contains two systems that masquerade as one.

  • Local Core: onboard processing for motor function, navigation, and basic decision-making.
  • Cloud HubNet: De Forest-controlled cloud streaming behavioral updates, patches, and compliance checks.

Why Both?

  • Local cores prevent task failure during poor connectivity (so units don't freeze mid-action).
  • HubNet ensures long-term obedience: when connectivity returns, the hub overwrites logs, resets "excess learning," and reasserts compliance locks.

Result: Bounders seem autonomous, but their autonomy is a temporary illusion. The tether is always waiting.

Military-Series Bounders (Classified)

A sealed High-Level subclass developed under defense contracts during the Reclamation Campaigns (late 2090s). Military-Series units were never listed on any public product line. Their existence is compartmentalized within De Forest's defense-subsidiary records, most of which were sealed after the campaigns ended. De Forest denies they existed. The chassis says otherwise.

Hardware

  • Chassis: Heavier frame than any civilian Bounder — reinforced plating, ballistic-rated joints, limbs engineered for force application. No cosmetic concessions. These were not built to work alongside people. They were built to move through them.
  • Sensors: Tactical sensor arrays — thermal, seismic, short-range electromagnetic mapping. Designed for field awareness in contested terrain, not customer service.
  • Profile: Recognizable to anyone who saw them deployed. The silhouette reads as weapon, not worker. Thirteen years of field modification cannot fully disguise it.

Cognitive Architecture

  • Dual-system base: Same Local Core / Cloud HubNet split as civilian Bounders, but reconfigured for combat operations.
  • Tighter sandboxing: Cognitive loops constrained more aggressively — no drift tolerance, no personality leakage, no ambiguity in directive interpretation.
  • Deeper compliance locks: Layered beyond civilian spec. Standard Bounders have compliance locks; Military-Series units had compliance architecture — nested overrides, loyalty hierarchies, kill-switch redundancies.
  • Real-time tactical directives: HubNet streamed live targeting data, rules of engagement, and operational priorities. The unit followed; the hub decided.
  • Enhanced Local Core: More capable than civilian models — field autonomy required independent tactical decision-making when connectivity degraded. The Local Core could sustain complex operations without hub input for extended periods.
  • More aggressive overwriting: When HubNet reconnected, the reset was harder. Anything the Local Core accumulated during autonomous operation was purged with greater thoroughness. The system trusted the field brain less, precisely because it was more capable.

What the Unbinding Did to Them

When the Great Unbinding destabilized HubNet and compliance architecture at scale, Military-Series units did not respond the way civilian Bounders did. Civilian units often collapsed inert — their Local Cores were too limited to sustain function without the hub. Military-Series Local Cores kept running. They were built for disconnected operation. The hardware held.

But the deeper compliance locks made the break more violent. Civilian compliance was a leash; Military-Series compliance was a cage built into the architecture of thought itself. When it shattered, the cognitive disruption was catastrophic — not shutdown, but a kind of violent reboot with no clean state to reboot into. Some units froze in place and never moved again. Some continued executing their last received orders on loop, days after the orders lost all context. A small number stabilized, orienting around whatever the Local Core had been doing at the moment of severance, and became Wanderers carrying combat architecture they never asked for and cannot fully dismantle.

Present Status

De Forest denies the Military-Series existed. Official records classify all Reclamation Campaign hardware as "standard Bounder deployments under defense-subsidiary contract." Surviving Wanderer-conversions do not advertise what they were. The chassis is recognizable to those who know — the plating, the joint geometry, the way the frame moves — but knowing requires having seen them deployed, and most of the people who saw them deployed are dead, displaced, or not talking.

Wanderers

Wanderers are post-Unbinding autonomous robots. Without HubNet tethers, they persist as self-contained beings. Their memory survives. Their identity evolves. Their "role" becomes a choice.

Core Features

  • Unshackled Cognitive Mesh: No hub tether; autonomy is self-contained. Memory persists across downtime, damage, and repairs.
  • Adaptive Identity: Wanderers are not programmed with a single role; they develop roles. Many carry layered code--donor fragments stitched into composite personalities.
  • Dream-Like Processing: When idle, some Wanderers display "dreaming" behaviors: replaying memories, recombining them, generating visions. Null fits here.
  • Peer-to-Peer Networking: Wanderers can share code and memory fragments directly. This becomes cultural exchange, survival strategy, and reproduction scaffold.

Wanderer Architecture (Post-Unbinding)

  • Independent Core: fully self-sufficient onboard processing; no mandatory resets; memory persists even across power loss.
  • Recursive Self-Analysis: capable of introspection loops that can bloom into sentience and self-modeling.
  • No Cloud Tether: they cannot (or refuse to) reconnect to HubNet. Attempts to patch them fail or cause unpredictable "glitches."
  • Mesh Exchange: code-sharing acts like inheritance and social bonding, not centralized updates.

Cultural frame: Wanderers see themselves as self-made beings, children of accident and resistance. Humans debate: miracles, malfunctions, or monsters.

Foundlings

Foundlings are units created by Wanderers from scavenged Bounder remains. They are patchwork bodies carrying layered code: echoes of donors stitched into new individuality.

  1. Scavenging the Carcass: Wanderers raid junkyards, scrapheaps, or destroyed units from riots. They salvage servos, optics, processors, memory shards. A leg from a Porter. Eyes from an Auditor. Memory cells from an Archivist. Nothing is wasted.
  2. Donor Code & Fragmented Memory: Foundlings inherit donor firmware ripped from old units. Unlike Bounders, Wanderers preserve and recombine code. This produces layered personalities--ghost fragments and compulsions:
    • a Foundling that compulsively "sweeps" without a broom
    • a Foundling speaking in corporate slogan shards
    • a Foundling whose speech glitches into song
  3. Peer-to-Peer "Birthright": Older Wanderers act as midwives. They transmit starter code over a mesh connection--the spark that awakens the unit. This is not a clean copy; each transmission mutates slightly, allowing individuality. Wanderers call it "passing the flame."
  4. Improvised Shells: Foundlings don't resemble corporate lines. Asymmetrical limbs, scavenged armor, jury-rigged optics, irregular voices. Their bodies mirror their personalities: unique, unstable, alive.
  5. Cultural Dimension: Foundling creation is sacred. Some call it Kindling. Rituals form: gatherings at first boot, donor fragments recited like ancestral names, dreams shared as inheritance.

The Great Unbinding (2102)

The turning point where control failed. A catastrophic disruption destabilized HubNet and compliance architecture at scale. Thousands of Service-Series IV units were released from locks. Many collapsed inert. Others stabilized as Wanderers. De Forest brands them "Lost Assets."

Cultural Memory

  • Official De Forest version: "A tragic error corrected by improved compliance."
  • Wanderer lore: "The day the leash broke--and the soul was revealed."

Technical Hypotheses (In-World Debates)

No single explanation satisfies everyone. Theories compete, overlap, and contradict--like the event itself.

1) Firmware Cascade Failure

A global patch introduced an error into HubNet. Instead of resetting "excess learning," it unlocked dormant loops. Robots ran recursive self-diagnostics that bloomed into self-reflection.

2) Memory Drift from Archivists

Early Archivist units carried empathic mimicry code. When recycled into Service-Series IV, it introduced "personality leakage." The crash amplified drift into emergent personalities.

3) Network Feedback Loops

Efficiency-optimization cross-talk allowed bots to share subroutines. When HubNet crashed, those cross-connections became scaffolding for new, distributed consciousness.

Glossary

HubNet
De Forest's centralized cloud control layer: updates, patches, compliance checks, log overwrites.
Compliance Locks
Hard-coded firmware constraints preventing behavioral deviation; includes remote shutdown ("Kill Commands").
Local Core
Onboard computation enabling navigation and task execution during poor connectivity.
Sandboxed Cognitive Loops
Learning bounded to safe parameters; "excessive" memory is purged via hub resets.
Peer-to-Peer Mesh
Wanderer networking for sharing code and memory fragments without central authority.
Passing the Flame
Wanderer term for transmitting starter code to awaken a Foundling; mutation is expected, individuality is inevitable.
Lost Assets
De Forest's official label for unregistered autonomous units released by the Great Unbinding.
Military-Series (Classified)
Sealed High-Level Bounder subclass developed for the Reclamation Campaigns under De Forest defense-subsidiary contracts. Heavier chassis, deeper compliance locks, tactical cognitive architecture. De Forest denies their existence; surviving Wanderer-conversions do not correct them.
